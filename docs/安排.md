## 一、16 周总览

**投入节奏**：约 10 小时/周（工作日 3 次 × 每次 1.5h + 周末一个 5h 整块）。
**原则**：节奏可以根据精力弹性微调，但技术演进的步骤不要跳。

**全局核心准则（防烂尾与防过拟合铁律）**：
1. **独立验收与防过拟合**：每个里程碑版本（v0.1 / v0.2 / v0.3 / 最终交付）必须事先设计好独立验收任务与人工预期（包含必须回答的事实、必要证据和不可接受的错误，而不仅是文件名与符号名），再冻结代码运行。凡是已经人工看过执行结果、并据此进行过调优的任务，自动转为“开发回归集”；重新证明泛化能力时，必须引入新的任务或外部工程分支。
2. **表述去泡沫化**：严禁在计划与验收中使用“100% 精准”、“无破坏”、“完整调用路径”、“零误报”、“铁证”、“彻底告别”等伪承诺；统一替换为客观的工程契约：“支持范围内的关系与未解析项（unresolved）”、“在已检查调用位置与已执行测试范围内，未发现破坏；其他行为尚未确认”、“记录误报数与原因”、“支持范围内正常分析，范围外明确降级”。
3. **时间预算与取舍**：每周约 10 小时是投入预算，日期是目标安排。基础能力未完成则顺延；优先缩减支持范围、延后扩展功能，不压缩验收，也不为赶日期增加特例。每周开始时只细化当周任务，后续模块名与接口允许按实际证据调整。
4. **流程测试与能力验收分开**：固定模型响应的自动化测试验证工具分发、预算退出、证据绑定与报告生成；真实模型的独立任务验收验证答案质量、证据支撑与成本。冒烟测试全绿不代表任务答案正确，两类结果分别报告。

### W1（09-21 ~ 09-27）· 交互底座与流式对话

> 深入点：**上下文多大时模型开始答不准（Token 压力测试）**。S3 的代码实验就是深入点本身。

#### S1（周一晚 · 1.5h）
- **核心代码任务**：
  1. 搭建 conda 环境与项目骨架，安装核心依赖（`langchain-core`、`langchain-deepseek`、`python-dotenv` 等）
  2. 调通 DeepSeek API 连接
  3. **【代码增量】** 实现 `stream_ask()` 生成器支持打字机式流式输出
  4. **【代码增量】** 实现基于控制台的交互式 CLI 循环（支持连续提问与简易上下文）
- **交付物**：`src/code_agent/core/model.py`、`src/code_agent/cli.py`（可交互流式 CLI）

#### S2（周三晚 · 1.5h）
- **核心代码任务**：
  1. 定义清晰的模型抽象层（`ChatModel` 协议/基类），使业务调用解耦
  2. 接入 `loguru`，记录每次调用的输入/输出 Token 数与响应耗时
  3. **【代码增量】** 使用 Pydantic 定义代码评审数据模型（`ReviewIssue`、`ReviewReport`）
  4. **【代码增量】** 编写代码审查 System Prompt，让模型按结构化 JSON 返回问题行号与建议
- **交付物**：模型抽象模块 + Pydantic 结构化输出模块 + 带耗时统计的日志

#### S3（周五晚 · 1.5h）
- **核心代码任务**：
  1. 编写实验脚本 `test_context_limit.py`
  2. 手动构造不同大小的代码上下文（从 100 行、500 行递增到 2000 行），要求模型“指出第 X 行的变量名”
  3. 记录不同 Token 长度下的响应耗时与幻觉拐点，数据记入极简笔记
- **交付物**：`tests/test_context_limit.py` + 一份上下文失效点测试数据

#### W（周末整块 · 5h）

  1. 安装 `rank_bm25`，编写最朴素的代码仓库索引器（遍历源文件 $\to$ 分词 $\to$ 构建倒排）

  3. 准备 5 条针对自己代码库的测试提问，验证关键词检索效果
- **交付物**：`src/code_agent/index/bm25_index.py` + CLI 关键词搜索功能可用

**验收标准**：在终端输入问题，CLI 能即时通过 BM25 查出代码片段，并流式给出带行号的回答。

### W2（09-28 ~ 10-04）· 出处与记账

- **交付物**：`eval/runs/baseline_bm25.json`（第一个基线数据）

### W5（10-26 ~ 11-01）· 向量与混合检索

> 深入点：**语法边界分块（AST）vs 固定滑动窗口对比，以及词法与语义双路召回的权衡与融合**。

#### S1（周一晚 · 1.5h · 语法感知切块）
- **核心代码任务**：
  1. 理解机械分块缺陷：回顾 W4 S2 中 60 行滑动窗口切块，分析其切断类定义、丢失函数签名与跨函数碎片导致多余 Token 消耗的物理缺陷。
  2. 基于标准库 `ast` 编写 Python 代码解析切块器（`src/code_agent/index/ast_chunker.py`）：
     - 递归解析模块语法树，按独立函数（`FunctionDef` / `AsyncFunctionDef`）和类（`ClassDef`）提取语义闭环的代码块；
     - 类内方法附带类名前缀（如 `ClassName.method_name`），完整保留函数签名与 Docstring；
     - 输出统一契约：文件相对路径、物理起止行号 `[start_line, end_line]`、符号名与代码文本。
  3. 增加防御降级机制：遇到语法解析错误（`SyntaxError`）或非 Python 文件时，平滑降级回退至基础滑动窗口切块。
- **交付物**：`src/code_agent/index/ast_chunker.py` + 针对项目真实代码（如 `citation.py`）的切块验证与切分对比。

#### S2（周三晚 · 1.5h · 语义向量检索）
- **核心代码任务**：
  1. 引入轻量级本地向量库（如 `chromadb`），免 Docker、纯本地文件持久化，配置轻量级嵌入模型（Embedding）。
  2. 编写向量索引器（`src/code_agent/index/vector_index.py`）：
     - 承接 AST 切块产物，构建向量索引并持久化元数据（`file_path`、`start_line`、`end_line`、`symbol_name`）；
     - 实现向量余弦相似度检索接口 `search(query: str, top_k: int = 3)`。
  3. 词法 vs 语义召回对照实验：选取 3 个概念意图性查询（如“如何校验引用合法性”、“模型如何做结构化输出”），对比纯 BM25 关键词与向量语义检索的召回差异，观察语义泛化能力。
- **交付物**：`src/code_agent/index/vector_index.py` + 向量语义检索召回效果对比记录。

#### S3（周五晚 · 1.5h · 双路召回与混合检索器）
- **核心代码任务**：
  1. 解决打分尺度不一致问题：BM25 得分无上限，向量距离为 `[0, 1]` 余弦相似度；设计 Min-Max 归一化或 RRF（倒数排名融合）算法抹平分值鸿沟。
  2. 实现混合检索器（`src/code_agent/index/hybrid_retriever.py`）：
     - 发起 BM25 与向量双路召回；
     - 对重复召回的代码块按权重融合打分（$\text{Score} = \alpha \cdot S_{\text{bm25}} + (1 - \alpha) \cdot S_{\text{vec}}$）；
     - 输出统一的 `CodeChunk` 结果列表，显式标注每个候选块的命中来源（BM25 命中 / 向量命中 / 双重命中）。
  3. CLI 交互升级：在 CLI `/search` 中接入混合检索器，直观展示命中代码块的融合得分与召回来源标签。
- **交付物**：`src/code_agent/index/hybrid_retriever.py` + CLI 混合检索集成与输出验证。

#### W（周末整块 · 5h · 评测大盘回归、消融实验与 ADR-001 决策闭环）
- **核心代码任务**：
  1. 评测执行器适配：在 `eval/run_eval.py` 中增加 `--retriever` 参数，支持无缝切换 `bm25` / `vector` / `hybrid` 检索策略。
  2. 全量 25 题自动化回归跑分：

## 六、附录 A · 技术选型与依赖规划

| 类别 | 选用方案 | 核心理由 |
|---|---|---|
| **运行环境** | Python 3.12+ (conda 独立环境) | 生态兼容最好，开发阻力最小 |
| **类型检查** | `mypy` | 强制关键数据模型与函数标明类型，杜绝类型隐患 |
| **模型调用** | `langchain-core` + 官方集成包（`langchain-deepseek` 等） | 统一的消息与工具接口抽象 |
| **检索组件** | 阶段 1~2: `rank_bm25` 纯关键词；阶段 3+: `chromadb` 或 `lancedb` 轻量向量库 | 循序渐进，从无向量对比到有向量对比 |
| **代码解析** | Python 标准库 `ast` | 按函数与类精准切块，无需第三方重型依赖 |
| **工作流编排** | 阶段 1~3: 原生 Python 循环；阶段 4~6: `langgraph` 状态图 | 先体会手写的痛点，再享受框架的红利 |
| **日志与工具** | `loguru` + `pydantic` + `pytest` | 现代 Python 开发标配 |
