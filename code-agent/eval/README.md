# eval（评测）

**这个目录是整个项目的地基。** 从 W1 第 1 天就开始往里放案例，不要等"功能做完再补"。

## 目录

- `cases/` —— 黄金集，一题一文件（`.yaml`），命名 `001-简短描述.yaml`
- `runs/` —— 每次跑分的结果，命名 `report-001.md`、`report-002.md`……
- `run_eval.py` —— 评分脚本（W3 写，**用 Python**）

## 案例模板

见 `../../安排.md` 附录 C.3（eval 案例），或直接复制 `cases/` 里那个示例文件。

## 案例从哪来

| 来源 | 怎么采集 | 占比 |
|---|---|---|
| **真实踩到的** | 每次找代码/找资料超过 5 分钟，就把那个问题记下来 | ≥ 50% |
| 熟悉模块的提问 | 你熟的业务点：在哪实现 / 为什么这么写 / 谁调用了它 | 30% |
| **边界问题** | 问库里根本不存在的东西，正确答案是"不知道" | 10% |
| 坑日志反哺 | 每条坑日志对应一条案例 | 10% |

**"真实踩到的"必须占一半以上。** 构造出来的问题偏向"能答对的"，会让分数虚高。

## 指标（W3 起固定）

| 指标 | 定义 |
|---|---|
| 完成率 | 给出了非空、非报错回答的比例 |
| **引用准确率** | 给出的引用中，文件存在且行号落在范围内、且确实包含答案依据的比例 |
| 平均 token | 每次提问的输入 + 输出 token |
| P95 延迟 | 95 分位响应时间 |

**引用准确率可以完全自动判定** —— 这是本项目 eval 能成立的根本原因。
